## 2024-05-18 - Cross-Site Scripting (XSS) via unescaped innerHTML
**Vulnerability:** Several functions in `index.html` used `innerHTML` to directly render user input, AI-generated content, or inputs attached to inline event handlers (like `onclick`) without any HTML escaping. This allowed malicious payloads to execute Javascript when those sections of the UI were displayed or interacted with.
**Learning:** Browsers decode HTML entities in inline event handler attributes (like `onclick`) *before* executing the Javascript. So if a string like `O'Reilly` is escaped as `O&#039;Reilly`, placing it inside `onclick="foo('O&#039;Reilly')"` gets decoded to `onclick="foo('O'Reilly')"` which creates a syntax error or a possible injection point.
**Prevention:** To prevent XSS via `innerHTML`, use explicit DOM APIs (like `textContent`) whenever possible. If `innerHTML` must be used, define an `escapeHTML` helper function and wrap all untrusted values before string interpolation. When interpolating untrusted values into inline event handler attributes (e.g. `onclick="handler('[value]')"`), the value must be *double-escaped*: first use a Javascript string escape (e.g. replacing `'` with `\'`), and then HTML-escape the result, so that the string is safely interpreted by both the HTML parser and the Javascript execution context.
