## 2024-05-24 - Double-Escaping Inline Event Handlers
**Vulnerability:** XSS vulnerability found in `index.html` where user input was rendered unescaped into the DOM, specifically inside an inline event handler (`onclick="removeFeature('...')"`).
**Learning:** Browsers decode HTML entities before executing JavaScript inside inline event handlers like `onclick`. Single-escaping (e.g., `escapeHTML` only) allows an attacker to break out of the string context in the JS execution if quotes or slashes are used, as HTML-escaped quotes (`&quot;`, `&#039;`) get decoded back to actual quotes before the JS executes.
**Prevention:** To prevent XSS in inline event handlers, the input must be double-escaped: first `escapeJSString` to handle JS string termination and escaping rules (newlines, backslashes, quotes), and then `escapeHTML` to prevent breaking out of the HTML attribute itself. E.g. `escapeHTML(escapeJSString(userInput))`. Alternatively, attach event listeners natively rather than using inline handlers.
