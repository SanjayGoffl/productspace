## 2025-05-18 - Missing input sanitization in innerHTML injections
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability found in `index.html`. Specifically, user-provided inputs (`product.features`, `competitors.name`, `competitors.domain`, `competitors.price`) were being injected directly into the DOM using `.innerHTML` inside template literals without any escaping.
**Learning:** This application makes heavy use of vanilla JavaScript to dynamically build and inject HTML components (like chips and competitor cards). When generating HTML via template literals and assigning it to `.innerHTML`, any unsanitized user input poses a critical XSS risk. Furthermore, when binding inputs to inline event handlers (e.g., `onclick="removeFeature('...')"`), the string must be doubly escaped: once for JavaScript context (escaping quotes) and once for HTML context (escaping entities), because browsers decode HTML entities before JavaScript execution.
**Prevention:** Always use dedicated `escapeHTML` and `escapeJSString` utility functions to sanitize user-provided data before using it in template literals that will be rendered via `.innerHTML`. Ensure inline event handler arguments receive both HTML and JS escaping to prevent execution context escapes.
