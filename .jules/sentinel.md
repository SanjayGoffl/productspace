## 2026-05-18 - [Missing escapeHTML function]
**Vulnerability:** XSS vulnerability through lack of input sanitization
**Learning:** We need to sanitize user input when generating dynamic HTML directly in client-side code to prevent Cross-Site Scripting (XSS).
**Prevention:** Implement and use an escapeHTML function to sanitize text input before inserting it into innerHTML.
## 2024-07-04 - Unsanitized LLM Output Injection in Market Simulation (XSS)
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability found in Phase 6 (`renderPersonaCard`) and Phase 7 (`renderPhase7`) where dynamic JSON output generated by LLM (such as persona names, emojis, choices, quotes, and features) was injected directly into the DOM using `innerHTML` without sanitization.
**Learning:** Even though the LLM is instructed to return structured JSON and the system enforces JSON schemas, the *content* within those JSON fields is untrusted and can contain malicious script payloads. Relying solely on JSON structure parsing does not prevent malicious script injections in vanilla JS frontends. Fields like `persona`, `product_chosen`, `quote`, etc., must still be explicitly sanitized.
**Prevention:** Always use `escapeHTML` for dynamic strings injected into the DOM via `innerHTML`, especially for data originating from LLMs or third-party APIs. For attributes with fallback values, apply the fallback inside the escaping function argument (e.g., `escapeHTML(data.emoji || '👤')`) to avoid runtime crashes or bypasses due to null/undefined inputs.
